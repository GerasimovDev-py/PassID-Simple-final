# PassID

Система учёта пропусков для контрольно-пропускных пунктов предприятия. Заменяет бумажный журнал: ответственное лицо оформляет заявку на пропуск, сотрудник охраны подтверждает вход и отмечает уход посетителя.

## О проекте

**PassID** — веб-приложение для автоматизации оформления и контроля электронных пропусков на территорию предприятия через несколько контрольно-пропускных пунктов. Ответственное лицо оформляет заявку на пропуск, сотрудник охраны на КПП подтверждает вход и фиксирует уход посетителя. Все операции сохраняются в базе данных, что исключает ручной учёт и потерю информации.

### Проблема

- Нет контроля заявок — непонятно, кто и когда оформил пропуск.
- Ошибки учёта — потерянные записи, двойные отметки, отсутствие истории.
- Сложный отчёт в конце месяца — всё сводится к ручному труду.

### Решение

- Автоматическая регистрация заявок — единая точка входа для всех КПП.
- Разграничение ролей — ответственное лицо, охрана, администратор.
- История посещений — видно, кто и когда приходил и уходил.
- Валидация данных — некорректные заявки не попадают в БД.

## Архитектура

Проект построен по паттерну **MVT** (Model — View — Template), принятому в Django. Каждый слой отвечает за свою задачу.

```
+-------------------------------------------------------------+
|                      Клиент (HTTP)                          |
+-----------------------------+-------------------------------+
                              | HTML, JSON
                              v
+-------------------------------------------------------------+
|                   urls.py (маршрутизация)                   |
|  - Сопоставление URL и view                                 |
+-----------------------------+-------------------------------+
                              | вызов view
                              v
+-------------------------------------------------------------+
|                     views.py (Django)                       |
|  - Обработка запросов                                       |
|  - Проверка ролей и сессий                                  |
|  - Вызов моделей                                            |
|  - Рендеринг шаблонов                                       |
+-----------------------------+-------------------------------+
                              | вызов ORM
                              v
+-------------------------------------------------------------+
|                       models.py                             |
|  - Visitor (заявка на пропуск)                              |
|  - Profile (расширение User)                                |
|  - Валидация на уровне полей                                |
+-----------------------------+-------------------------------+
                              | SQL
                              v
+-------------------------------------------------------------+
|                  PostgreSQL (Supabase)                      |
|  - core_visitor (id, full_name, document_*, kpp, status)    |
|  - core_profile (user_id, kpp, is_responsible, *)           |
|  - auth_user (стандартная модель Django)                    |
+-------------------------------------------------------------+
```

- Python 3.11+
- PostgreSQL (локально или Supabase)

### Шаги

```bash
# 1. Клонировать репозиторий
git clone https://github.com/GerasimovDev-py/PassID-Simple-final.git
cd PassID-Simple-final

# 2. Создать виртуальное окружение
python -m venv venv

# 3. Активировать
# Windows:
venv\Scripts\activate
# Linux/Mac:
source venv/bin/activate

# 4. Установить зависимости
pip install -r requirements.txt

# 5. Создать файл .env в корне проекта

env
SECRET_KEY=your-secret-key-here
DEBUG=False

Статические файлы
Сбор статики выполняется командой collectstatic в каталог STATIC_ROOT. Раздача на продакшене — через WhiteNoise (middleware).

Настройки безопасности
При DEBUG=False активируются:

SECURE_SSL_REDIRECT = True

SESSION_COOKIE_SECURE = True

CSRF_COOKIE_SECURE = True

Безопасность
CSRF-защита всех POST-запросов.

Хеширование паролей средствами Django (PBKDF2).

Разграничение прав доступа на уровне представлений и сессий.

Хранение секретов в переменных окружения (.env).

Принудительный HTTPS на продакшене.

Защита от SQL-инъекций за счёт использования ORM.

Явное указание ALLOWED_HOSTS для предотвращения Host Header Injection.

Логирование
Проект использует стандартный модуль logging Django.

Уровень	Когда
DEBUG	Отладка, SQL-запросы (при DEBUG=True)
INFO	Успешные операции, вход/выход
WARNING	Бизнес-ошибки (неверный пароль, нет доступа)
ERROR	Ошибки БД, исключения
Логи WSGI-приложения доступны на PythonAnywhere в разделе Web → Log files → Error log.

Обработка ошибок
HTTP-коды
Код	Название	Когда
200	OK	Успешная операция
302	Found	Редирект после входа / выхода
400	Bad Request	Некорректный запрос
403	Forbidden	Нет прав доступа
404	Not Found	Заявка или пользователь не найден
500	Internal Server Error	Ошибка БД или неизвестная ошибка
Свои исключения
Стандартные исключения Django используются без изменений:

DisallowedHost — неверный HTTP_HOST (проверить ALLOWED_HOSTS).

PermissionDenied — нет прав доступа.

Http404 — объект не найден.

ValueError — ошибки бизнес-логики.
